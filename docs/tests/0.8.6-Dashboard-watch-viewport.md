# 0.8.6 — Dashboard watch viewport test result

## Regression coverage

`windowBody`, `scrollKeys` and `nextScroll` are pure and exported, so the
viewport is covered without a TTY:

- **windowBody** — with a 5-row header, a 20-row body, height 10 and one footer
  row reserved, the window is 4 rows and `maxScroll` is 16. The header is
  asserted deep-equal at every scroll position. Scrolling past the end clamps to
  the last page (and the last body row is visible there); a negative scroll
  clamps to 0. Without a finite height nothing is windowed — the one-shot
  dashboard path. A body that fits reports `maxScroll` 0, which is what
  suppresses the footer hint.
- **scrollKeys** — `↑ ↓ PgUp PgDn Home End k j g G q` all map, an unhandled key
  returns null, and a chunk carrying several keys resolves to the last.
- **nextScroll** — clamps at both ends, pages with overlap, and stays at 0 when
  there is no scroll room.

The existing watch test additionally asserts the loop wiring: the `resize`
listener, the full repaint it triggers, and the `nextScroll` call.

## Manual verification

The real watch loop was driven against a stubbed TTY (14 rows): the initial
frame showed `1-8/20` with the header pinned, `G` moved to `13-20/20` with
gamma visible and the header still pinned, `g` returned to `1-8/20`, and a
resize to 40 rows repainted every project with no scroll indicator.

Inter-project spacing was checked against a three-project store: a blank line
and a rule now separate blocks, one row tighter than before.
