# 0.8.5 — Invalid-history recovery test result

## Regression coverage

Two tests, each damaging a worklog the way a real one drifts — a `handoff.start`
left as `unknown` while its own session records name a worker, and intents
stranded after their session's `handoff.end`.

- **`compact --archive-invalid`** — plain `compact` refuses and its message
  names the flag. `--keep 5 --archive-invalid`, which would leave invalid
  records live, refuses with the largest workable `--keep` and writes no archive
  directory at all. `--keep 3 --archive-invalid` archives the prefix, reports
  the 5 historical errors that moved with it, leaves a live worklog that
  verifies, and allows `start` again. The archived file is asserted deep-equal
  to the damaged records: moved, not rewritten.
- **Seq-bounded disposition** — a write is refused and its message names
  `--operator-disposition`. After the disposition, `throughSeq` is 8 in Lane
  metadata and the full `start` / `intent open` / `intent promote` / `end` cycle
  succeeds, while `verify` still exits 1 on the acknowledged history. Damaging a
  record above the acknowledged seq blocks writes again, listing only the new
  failures (`line 10:`) and not the acknowledged ones (`line 2:`).

## Manual verification

Reproduced the reported server state (`ahp compact --keep 3` refusing on 17
errors, writes blocked, `--lenient` not helping) in a throwaway store on 0.8.4,
then confirmed both routes clear it on this build.
