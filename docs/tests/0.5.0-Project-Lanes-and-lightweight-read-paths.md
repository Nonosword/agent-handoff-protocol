# 0.5.0 — Project Lanes and lightweight read paths

## Scope

This report covers Lane creation/selection/editing, legacy compatibility,
shared-commit associations, bounded pickup output, dashboard watch cost, MCP
parity, registry safety and stale-lock recovery.

## Functional evidence

- First `start` auto-creates a Lane; other write commands fail clearly when no
  Lane exists.
- A sole Lane and the sole Lane held by the current worker auto-select.
- Multiple plausible Lanes produce existing descriptions plus a new-Lane
  choice; `--lane` resolves explicitly.
- One commit can be promoted in two Lane worklogs without deduplication or
  rejection; a commit promoted only in another Lane is not falsely reported as
  unmatched when both Lanes share a branch.
- Title/alias collisions, malformed entries and path-unsafe ids fail closed.
- Unicode titles produce readable Lane ids; a dead/stale Lane-registry lock is
  reclaimed.
- `project current` stays Project-only and cannot be blocked by Lane ambiguity.
- CLI and all three Lane MCP tools operate on the same metadata.
- Existing worklogs remain the synthetic `main` Lane.

## Pickup bounds

The compact default emits at most 10 commits, prioritising up to 8 unmatched
commits, plus at most 5 open intents and 10 dirty paths. A 12-unmatched-commit
fixture emits 8 and reports the other 4 explicitly; `--full` emits all 12.
Historical promotion reachability checks run only under `--full`.

No token estimate is printed: it would be model/tokenizer-dependent and less
reliable than the exact item counts. There is one expansion control,
`--full`, rather than several overlapping limit parameters.

## Dashboard watch cost

The previous watch render performed roughly 5–7 Git subprocesses per Project
per interval (repository checks, branch, HEAD, status and, when a base existed,
history reconciliation). The steady 0.5.0 fingerprint performs exactly one Git
subprocess per Project: branch plus short HEAD. This is an 80%–86% reduction in
Git process count, and removes working-tree/history scans from steady polling.
Unchanged fingerprints produce no terminal redraw.

Dashboard Lane support adds a small `lanes.json` read plus file metadata checks. Full
worklogs are parsed only for an initial/changed frame, not on every unchanged
watch interval. Work scales linearly with registered Projects and visible
Lanes. Pickup reads promotion records from other Lane worklogs only when the
selected base has commits to reconcile; this adds no Git subprocess and prevents
false unmatched warnings on a shared branch.

## Local timing sample

Observed on the development Mac with Node 24.2.0 and the current three-Project
store; timings include starting a fresh Node CLI process:

| Command | Runs | Result | Output |
| --- | ---: | ---: | ---: |
| `ahp dashboard --json` | 20 | mean 74.8 ms, p50 74.1 ms, p95 75.7 ms | 5,444 B |
| `ahp pickup` | 10 | p50 134.8 ms | 1,225 B |
| `ahp pickup --full` | 10 | p50 181.1 ms | 1,531 B |

The full/compact pickup difference in this small real log is about 46 ms at
p50. Larger histories increase the value of keeping historical reachability and
unbounded output behind `--full`; the compact output cap remains fixed.
