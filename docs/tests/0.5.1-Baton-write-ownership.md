# 0.5.1 — Baton write ownership test result

## Scenario

The regression creates a Lane owned by `codex`. It verifies that `qoder` cannot
open, promote, or end records while that baton is active. It then starts a
new `qoder` session, confirms the former `codex` worker cannot end it, and
confirms `qoder` can promote the inherited open intent and close its own baton.

## Atomicity evidence

The CLI supplies lifecycle preconditions to `appendRecord`; the function takes
the Lane lock, re-reads the worklog, evaluates the precondition, derives the
current session fields and only then appends/fsyncs. There is no unlocked
snapshot between ownership validation and append.
