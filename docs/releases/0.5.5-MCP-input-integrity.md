# 0.5.5 — MCP input integrity

## Outcome

The MCP adapter now treats its JSON schema as an enforced server-side boundary,
not merely a hint for well-behaved MCP hosts.

## Changes

- `tools/call` requires an object for `arguments`; malformed argument values
  receive JSON-RPC `-32602` invalid-params responses.
- Required text arguments must be present, strings, and non-empty. Optional
  supplied strings, booleans, finite numbers, string arrays, and enum values
  are type-checked before any CLI argv is constructed.
- Unknown tool names and absent tool names are rejected before spawning the
  CLI. The adapter therefore never applies `String(undefined)` to a write
  argument and cannot persist the literal text `undefined` as a record field.
- Malformed JSON frames receive the standard JSON-RPC `-32700` parse-error
  response instead of being silently dropped. Invalid JSON-RPC envelopes are
  reported as `-32600` invalid requests.

## Verification

The regression sends malformed JSON, a missing required `plan`, a numeric
`gate`, and a non-object `arguments` value directly to the MCP stdio server. It
checks each protocol error code and confirms that the target worklog remains
empty.
