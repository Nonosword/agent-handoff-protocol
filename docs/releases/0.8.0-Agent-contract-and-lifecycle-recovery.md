# Release - Agent contract and lifecycle recovery - 0.8.0

Released 2026-09-10.

## Agent-facing contract

- MCP now exposes `ahp_project_list`, allowing a Desktop agent with no inherited
  Git working directory to discover stable registered Project ids, roots and
  remotes before selecting a Lane.
- Project-scoped examples and runtime follow-up messages retain an explicit
  `--lane <id>` (or MCP `lane`) from pickup through session completion. The
  completion contract now states both operations: `handoff.end` releases the
  session baton, while `lane edit --status done` completes the Lane.
- Codex, Claude Code and generic-agent instructions carry the same Project
  discovery, Lane lifecycle, completion and operator-boundary rules.

## Integrity and lifecycle recovery

- A write using an explicit unknown Project id now fails with a registration or
  checkout recovery path. It can no longer create an orphan worklog omitted by
  `project list` and the Dashboard.
- Every `handoff.start.continuesFrom` now points to the immediately preceding
  start. Explicit stale or invented sequence values are rejected while the
  append lock is held; a failed attempt to reopen a done Lane restores `done`.
- Lane registry replacement uses the same durable atomic-write primitive as the
  rest of the store.
- A Lane with immutable historical validation failures remains visibly invalid,
  but an operator may explicitly disposition its exact SHA-256-bound worklog so
  it can become `done` or `archived`. MCP and agent instructions cannot invoke
  this operator-only escape hatch.

## Input and reporting consistency

- MCP schemas are closed (`additionalProperties: false`), all parameters have
  descriptions, and integer fields reject fractions, unsafe integers and values
  below their documented minimums.
- CLI `read --since/--tail` applies the same bounds; `--tail 0` returns no rows.
- Dashboard text and JSON modes now use the same strict failure rule for warnings.
- Installer self-test reports the live MCP `tools/list` count instead of a
  hard-coded value that can drift when tools are added.
- The relay example and English/Chinese documentation match the enforced
  continuation and Lane lifecycle contracts.

## Compatibility

The worklog record schema is unchanged. The added MCP tool and stricter rejection
of malformed or ambiguous inputs are additive/hardening changes. Hosts must
respawn their MCP server process to see the new tool list after installation.
