# 0.4.1 — Read-only pickup and actionable store diagnostics

Released 2026-09-07.

## Outcome

- The previously staged `ahp upgrade` command now ships with this release,
  including its fast-forward safety checks and host refresh guidance.
- Project discovery by `status`, `pickup`, `read`, `log`, `verify`,
  `path`, and `project current` is genuinely read-only. An unregistered Git
  checkout is identified ephemerally; its first AHP write performs registration.
- Store access failures name the denied operation and canonical target, retain
  the underlying OS code and syscall, report available process/owner/mode/access
  evidence, give a conservative likely-cause classification, state whether a
  record was written or may have been written, and tell the agent how to
  diagnose, obtain access, verify, and retry.
- A missing registry is still a fresh store. An unreadable or malformed registry
  now fails closed and is never treated as empty or overwritten.
- Agent instructions now define explicit success, fail-closed behavior, and the
  no-fallback rule for required AHP actions.
- `pickup` tests commit reachability through Git instead of misclassifying
  promotions that merely predate the latest handoff base.
- Dashboard titles include the running package version. `Agent Handoff` stays
  blue without bold; the baton summary uses ANSI 256-color gray `250`; projects
  are separated by a 58-character rule. JSON snapshots also expose `version`.

## Compatibility

The JSONL record format and existing stores are unchanged. This is a patch
release: it removes unintended writes and clarifies the existing requirement
that pickup precedes project changes.
