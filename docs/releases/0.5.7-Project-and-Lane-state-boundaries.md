# 0.5.7 — Project and Lane state boundaries

## Lane status safety

An active baton makes a Lane operationally live. `ahp lane edit <lane>
--status archived` now refuses while that baton is held, explaining that the
worker must first write `handoff.end` or choose a non-archived status. Once the
baton is released, archive remains available as before.

This keeps `archived` aligned with its existing selection semantics: archived
Lanes are not selected for new writes, so AHP must not place the current holder
in a state where it cannot end its own session.

## Project names

- New project registration and rename operations reject a name already used by
  another project. Stable project IDs remain the unambiguous selector.
- Existing central stores may contain duplicate historical names. Resolving one
  now fails closed and lists the colliding IDs, rather than silently selecting
  the first registry entry.

## Verification

The regression covers both state transitions: archive fails while a Lane baton
is held and succeeds after a clean end; duplicate new names are rejected, while
a hand-edited old registry with duplicate names reports a clear ambiguity.
