# 0.5.3 — Worklog integrity

## Outcome

This reliability release makes compaction, strict verification, and central
store mutation uphold AHP's append-only and handoff-ownership guarantees.

## Compaction

- `ahp compact` now obtains the selected Lane lock and re-reads the worklog
  while holding it, so it cannot overwrite a concurrent append.
- It accepts only a safe integer `--keep` value of at least one.
- It retains the complete source session for every unpromoted intent and every
  promotion that remains live, and does not archive a hard-cutoff session. A
  live worklog can therefore never begin with an orphaned `intent.open` or
  contain a promotion whose open record was archived.
- Archive and live files are written through a temporary file, synced, and
  atomically renamed. An archive is published first; if replacing the live
  worklog fails, the original log remains intact and retrying is idempotent.

## Verification and storage safety

- The validator now enforces the JSON-schema record types and key constraints
  for worker identity, state objects, strings, arrays, intent IDs, and
  `continuesFrom`.
- Intent and end records must belong to the active baton owner. These are
  lifecycle errors, not warnings that `--lenient` can hide.
- Every non-pass `handoff.end` must include findings, rather than only the
  final end record in a stream.
- Locks no longer delete a file after a non-`EEXIST` acquisition failure and
  never reclaim a lock solely because its owner has been alive for 60 seconds.
  Lock releases are token-checked. Appends use full-write loops, and the shared
  project registry now has a global read-modify-write lock.

## Deliberate boundary

This release keeps AHP's local CLI + JSONL architecture. It does not introduce
a daemon, database, or network service. Installer JSON merge, MCP malformed
input handling, and upgrade-contract work remain separate follow-up concerns.
