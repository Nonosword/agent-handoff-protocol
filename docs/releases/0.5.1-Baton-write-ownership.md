# 0.5.1 — Baton write ownership

## Outcome

This safety release prevents one worker from appending `intent.open`,
`intent.promote`, or `handoff.end` to another worker's active Lane session.
The check runs under the same file lock and freshly read worklog snapshot as the
append, so it closes the former check-then-append race.

## Deliberate boundary

`handoff.start` is unchanged: it remains the explicit recovery route after a
cutoff. Once a worker has picked up and started its own session, it may finish an
open intent inherited from the prior session. The release blocks accidental
cross-worker writes; it does not turn AHP into a multi-writer coordinator or
forbid documented cutoff recovery.

## MCP attribution

An MCP process now treats empty inherited `AHP_WORKER_ID` and `AHP_RUNTIME`
values as unspecified, allowing the already detected `clientInfo` identity to
reach the CLI. A non-empty explicit environment value still wins.

## Verification

- 42 end-to-end tests pass.
- Regression coverage rejects foreign `intent.open`, `intent.promote`, and
  `handoff.end`, then confirms that a deliberate takeover can promote the
  inherited intent and end its own session.
