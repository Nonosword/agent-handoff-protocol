# 0.5.0 — Project Lanes and lightweight read paths

## Outcome

AHP now separates repository identity from work-stream identity. A **Project**
locates the Git repository; each **Lane** owns an independent append-only
worklog and baton. This keeps unrelated features in one large repository from
sharing one noisy continuity stream while preserving existing logs as the
synthetic `main` Lane.

## Lane resolution

- No Lane: the first `start` creates one from its plan.
- One selectable Lane, or exactly one held by the current worker: select it.
- Clear metadata match: the agent passes `--lane` without asking.
- Genuine ambiguity: show existing Lane descriptions plus a new-Lane option and
  ask the operator.

Agents create concise title/description/scope/alias metadata; humans may revise
it with `lane edit`. The same commit may be associated with intents in multiple
Lanes. Pickup consults those cross-Lane associations before reporting a commit as unmatched. AHP neither deduplicates associations nor chooses whether the code
should use a shared branch, a dedicated branch, or a worktree.

## Bounded reads

`pickup` keeps one simple default and one expansion flag. The compact view emits
at most 10 commits (prioritising unmatched commits), 5 open intents and 10 dirty
paths; `--full` expands all entries and enables historical reachability checks.
This bounds agent context without hiding the total or the fact that unmatched
commits were omitted.

Dashboard watch now polls Lane metadata/worklog fingerprints and one cheap
branch/short-HEAD view per Project. Working-tree scans, history scans and
unchanged redraws are absent from the watch loop.

## Compatibility

The worklog record schema is unchanged. Existing project-wide worklogs are
usable without migration through the synthetic `main` Lane. New named Lanes are
stored outside the project repository alongside AHP's existing central data.

## Verification

- 41 end-to-end CLI, lifecycle, Lane, compact-pickup, dashboard and MCP tests.
- Lane registry validation rejects unsafe ids and ambiguous routes; stale locks
  left by a cut-off process are reclaimed.
- Bundled example worklogs validated against the unchanged record contract.
