# 0.8.5 — Invalid-history recovery

## Outcome

A Lane whose history fails strict verification was unrecoverable in place.
`compact` and every append both validate the whole worklog and hard-refused;
`verify --lenient` downgrades warnings, not errors; and an operator disposition
moved the Lane's lifecycle status without unblocking either. Historical records —
written before a rule existed, or by a session whose `handoff.start` lost its
worker identity — therefore froze the Lane: nothing could be compacted away and
no new session could be opened.

This release gives the operator two ways out. Neither rewrites a record, and
neither makes verification pretend to pass.

## `compact --archive-invalid`

Moves an invalid prefix into `archive/<firstSeq>-<lastSeq>.jsonl`.

- Refuses unless the retained live worklog verifies on its own.
- Decides before publishing anything. A refusal writes no archive file, and
  names the largest `--keep` that would clear the Lane.
- Moves whole lines only, so every archived record stays readable.
- Waives only the "never archive a hard-cutoff session" guard, which otherwise
  re-blocks the recovery it exists to protect. Open-intent preservation still
  applies.
- Not the default: plain `compact` still refuses, and now names this flag.

Replacement validation also moved ahead of the archive write, so a compaction
that cannot produce a valid live worklog leaves no trace at all.

## Seq-bounded operator disposition

`lane edit <id> --status done --operator-disposition "<reason>"` now stores the
highest reviewed `seq` next to the worklog hash, and acknowledges history
**through that seq only**.

- A new `start --lane <id>` may append over acknowledged records, so the Lane is
  usable again without moving anything.
- `verify` keeps reporting the acknowledged failures. The disposition
  acknowledges history; it does not clear it.
- A failure above that seq is new and unreviewed: the write is still refused,
  and only the new failures are listed.
- An error the implementation cannot attribute to a seq is always blocking.
- Dispositions written before this release carry only the hash and stay
  readable; `throughSeq` is optional in Lane metadata.

## Messages

Both refusals now name the way out — `compact --archive-invalid` and the
operator disposition — rather than only stating the problem. The skill, the
Codex `AGENTS.md` snippet, `generic-agent.md` and `mcp.md` tell agents to stop
and report such a refusal for the operator to resolve, and never to invent or
run either route themselves.

## Spec

SPEC §9 records the archive-invalid opt-in and its obligations; the Lane
lifecycle section records the seq bound and that an implementation may let a new
session append over acknowledged history.
