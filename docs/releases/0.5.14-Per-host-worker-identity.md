# 0.5.14 — Per-host worker identity

## Outcome

The installer already wrote `AHP_WORKER_ID` / `AHP_MODEL` / `AHP_RUNTIME` into
each host's MCP `env`, so **tool**-written records are attributed. A bare `ahp`
**CLI** call an agent runs in a shell had no such hint and fell back to walking
the ancestor process tree for a known agent name. That misattributes whenever
one agent host launches another — a Codex shell whose nearest agent ancestor is
a Claude process resolves to `claude`, and since 0.5.1 the Lane baton-ownership
check then refuses the write.

The installer now also wires the identity into each host's own **shell**
environment, so the CLI path is attributed the same way as the MCP path.

## What changed

- **Claude Code** — `AHP_WORKER_ID` / `_MODEL` / `_RUNTIME` are merged into
  `~/.claude/settings.json` under `env` (injected into every Bash-tool shell).
  A locked, atomic single-leaf merge: unrelated keys and existing `env` entries
  are untouched; an unparseable file is left alone with a warning.
- **Codex** — the same keys are merged into `~/.codex/config.toml`
  `[shell_environment_policy.set]` (applied to every command Codex runs). There
  is no `codex config` write CLI and no zero-dependency TOML parser, so the edit
  is line-scoped: only lines inside that one table are ever touched, the rest of
  the file is preserved byte-for-byte, and the pre-edit file is copied to
  `config.toml.ahp.bak`. An inline `set = { … }` table is not rewritten — the
  installer prints a snippet to add by hand.
- **Qoder / Qoder CN** — no stable shell-env target; identity still comes from
  the MCP `initialize` handshake. Their MCP registrations now also carry an
  explicit `qoder` `env` as a default.
- `register_host` re-registers an MCP entry that points at this checkout but is
  missing the worker-identity `env`, not only one whose command path drifted.
- `--uninstall` removes exactly the identity keys it added, restoring
  `settings.json` and `config.toml` to their prior content.

## Docs

The skill, the Codex `AGENTS.md` snippet, `generic-agent.md` and `adoption.md`
no longer suggest a global `export AHP_WORKER_ID` in a shell rc file: one such
export applies to *every* agent launched from that shell, so two agents sharing
an rc file would write under one identity. They point at the per-host wiring and
the `--worker-id/--model/--runtime` flags instead.

## Verification

Isolated installer regressions: identity is merged into a seeded
`settings.json` and `config.toml` without disturbing unrelated content; a
second run rewrites nothing; `--uninstall` restores both files; a Codex config
with no shell-env table gets one appended; a Codex config with an inline
`set` table is left untouched with a printed snippet.
