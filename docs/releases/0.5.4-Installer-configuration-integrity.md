# 0.5.4 — Installer configuration integrity

## Outcome

The installer now updates JSON-backed MCP host configuration through a durable,
conflict-aware merge rather than directly truncating and rewriting the file.

## Safe JSON MCP updates

- `json_mcp_op()` uses a short, token-checked per-file lock for cooperating AHP
  installer processes. A dead lock owner is reclaimed; a live or unreadable
  lock is never deleted.
- It reads and parses the complete host document, changes only the
  `agent-handoff` entry under the host's configured MCP key, and preserves all
  unrelated top-level fields and servers.
- Before replacing the file, it re-reads a SHA-256 fingerprint. If a host or
  other program changed the document after the initial read, the installer
  re-reads and merges once from current content. Repeated concurrent changes
  fail clearly and leave retry to the operator.
- The replacement writes a uniquely named temporary file, completes the write,
  calls `fsync`, then atomically renames it into place. A partial write therefore
  cannot leave a truncated JSON configuration at the target pathname.
- Parse failures still leave a host configuration untouched and produce the
  existing actionable installer warning. Lock cleanup applies on unchanged,
  absent, parse-error, and failed-update paths.

## Deliberate boundary

This is best-effort optimistic concurrency for third-party host files. An
uncooperative host can still modify a file in the narrow interval after the
final fingerprint check and before rename; no portable filesystem API provides
a cross-process compare-and-swap for arbitrary host writers. The installer
detects changes before replacement, serializes AHP's own updates, and never
uses direct truncate/write.
