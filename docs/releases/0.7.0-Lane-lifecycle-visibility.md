# Release - Lane lifecycle visibility - 0.7.0

Released 2026-09-10.

## Lifecycle

- Lanes now have three user-facing states: `active`, `done`, and `archived`.
  The former `blocked` metadata value remains readable for old registries but
  cannot be assigned or written to; blockage stays a session end reason and
  finding.
- Moving to `done` or `archived` requires the Lane baton to be free, every
  intent to be promoted, and strict worklog verification to pass. Both status
  checks and the registry update run while holding the Lane worklog lock.
- An explicit `ahp start --lane <done-id>` changes the Lane to `active` before
  starting its next session. Implicit start never reopens completed work, and
  an archived Lane must be explicitly unarchived before reuse.

## Discovery and presentation

- `ahp lane list` and `ahp_lane_list` return active and done Lanes by default,
  preventing agents from overlooking completed matching work and creating a
  near-duplicate. CLI `--all` and MCP `all:true` add archived history.
- Automatic selection prefers active Lanes. If there is no active Lane but done
  work exists, a new start presents the completed choices and the new-Lane
  option rather than guessing.
- Dashboard keeps active Lanes expanded, renders done work as a compact count,
  and hides archived Lanes. JSON follows the same active-plus-done visibility.
  Watch mode remains filesystem-event-driven and does not poll to age labels.
- The human Dashboard continues to show only each Lane's title. Stable ids
  remain available in management lists, CLI/MCP selection, and JSON.

## Compatibility

- Worklog records and schemas are unchanged.
- Existing `blocked` Lane registry entries remain loadable and visible. Change
  them explicitly to `active` or `done` before appending new records.
- Archived promotion associations remain available to pickup reconciliation
  even though archived Lanes are hidden from normal task discovery.
