# 0.5.6 — Upgrade and schema contracts

## Upgrade network boundary

The network contract now states the actual behaviour: normal AHP CLI, MCP,
dashboard, validation, and installer operations do not initiate network
requests. Only a user-explicit `ahp upgrade` runs `git fetch` against AHP's own
configured checkout remote; it never fetches a user project.

`ahp upgrade` now returns non-zero when its post-update host refresh fails or
when the expected installer is missing. A pulled Git revision alone is no
longer reported as an all-successful host upgrade.

## Reproducible schema validation

- AJV 8 and `ajv-formats` are declared development dependencies and locked in
  `package-lock.json`; runtime dependencies remain zero.
- `npm run schema:check` now works from a normal clean checkout without a
  separate ad-hoc install command.
- CI installs locked dependencies with `npm ci` and runs the schema check
  directly, rather than downloading undeclared packages during the job.

## Verification

The upgrade regression proves that a failing `install.sh` gives `ahp upgrade`
exit status 1 after a successful Git update. The network-contract regression
asserts that the only permitted remote fetch is the explicit upgrade path.
