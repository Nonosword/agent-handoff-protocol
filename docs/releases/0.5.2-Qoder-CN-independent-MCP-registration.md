# 0.5.2 — Qoder CN independent MCP registration

## Outcome

The installer now treats Qoder and Qoder CN as two independent hosts. Detection
reports each product separately using its own CLI, application and user config
locations. Qoder CN is not an alias for `qoder` and never enters the normal
`qoder mcp add/list/remove` path.

## Registration contract

- **Qoder** uses the detected `qoder` CLI and its `mcp add/list/remove` API.
- **Qoder CN** uses the detected `qoder-cn` CLI and exactly one registration
  interface: `--add-mcp <JSON>`.
- On macOS the CN fallback CLI is
  `/Applications/Qoder CN IDE.app/Contents/Resources/app/bin/qoder-cn`; its
  independent MCP config is `~/.qoder-cn/mcp.json`.
- CN registration checks that dedicated JSON for a current AHP entry. CN has no
  remove CLI, so uninstall uses the existing safe JSON parse-and-merge delete
  only for `agent-handoff` in that dedicated file.

## Verification

- An isolated dry-run test with only Qoder CN present proves the installer emits
  `qoder-cn --add-mcp <JSON>` and never emits normal `qoder mcp add`.
- A real local dry run detected Qoder CN 1.28.0 at the bundled app CLI, planned
  only its `--add-mcp` command, and left `~/.qoder-cn/mcp.json` unchanged.
