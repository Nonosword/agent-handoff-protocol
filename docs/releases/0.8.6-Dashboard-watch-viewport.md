# 0.8.6 — Dashboard watch viewport

## Outcome

`ahp dashboard -w` paints into the alternate screen, which has no scrollback.
Anything past the terminal height was therefore replaced by a stub —
`… N more row(s); enlarge terminal` — and there was no way to reach it short of
resizing the window. Once a store holds more than a screenful of projects the
watch view stopped being usable at all.

The watch view now owns a real viewport.

## Viewport

- The header (title, rule, lifecycle summary) and the footer stay pinned; only
  the project body scrolls.
- Keys: `↑`/`↓` and `k`/`j` by line, `PgUp`/`PgDn` and `b`/space by page, `g`
  and `Home` to the top, `G` and `End` to the bottom, `q` to quit alongside
  ctrl-c. A page keeps a few rows of overlap so the reader keeps their place.
- The footer shows the visible range (`13-20/20`) and the key hints, but only
  while there is something to scroll — a body that fits is left alone.
- Scroll position is clamped to the content, so a resize or a store change can
  never leave the view parked past the end.
- The one-shot `ahp dashboard` is unchanged: it emits the full text and the
  terminal scrolls it.

`drawFrame`'s own height guard is kept as a last resort for a terminal too
short to hold even the header.

## Deliberate omission: mouse

Mouse reporting would let a click collapse a project, but enabling it takes
terminal text selection away from the user for the whole session — a worse
trade than a scroll key. If collapsing is wanted later, a keyboard toggle is the
route that keeps selection intact.

## Resize

A resized terminal changes the window height, and the terminal clears the
alternate screen itself. The watch loop now listens for `resize` and repaints
from scratch rather than diffing against rows that are no longer on screen.

## Spacing

Project blocks were separated by a blank line, a rule, and another blank line.
The rule already reads as a break, so the blank below it is gone: one row per
project boundary returned to content.

## Verification

`windowBody`, `scrollKeys` and `nextScroll` are pure and covered directly. The
watch loop was additionally driven end to end against a stubbed TTY —
initial frame, `G` to the bottom, `g` back to the top, and a resize — confirming
the header stays pinned and the visible range tracks the scroll.
